# Communication taste
- Prefers tightly scoped outputs: "reply with ONLY the prompt in one code block" plus a short list of facts that could not be found; minimal surrounding prose. Confidence: 0.7
- Agent ambiguity rule (AGENTS.md): ask at most ONE focused question when a task is genuinely ambiguous; otherwise decide and state the choice made rather than stalling or returning open-ended questions. Confidence: 0.7
- Writes long structured specs with numbered parts and "copy these rules exactly" instructions, expecting the agent to follow the requested structure verbatim rather than paraphrase, reorder, or embellish. Confidence: 0.75
- Names the downstream executor model and its weaknesses in the brief (e.g. "write for Gemini, which is weak at vague instructions") — wants prompts targeted at a less capable implementer with exact paths, signatures, defaults, edge cases, and an open-questions section. Confidence: 0.7
- Uses STEP 1 / STEP 2 / STEP 3 sectioning with explicit phase transitions ("read the code", "write the prompt", "output") and expects each step to be completed in order before the next. Confidence: 0.7
- Prefers long, copy-paste-ready prompts to be delivered as a `.md` file in the repo (e.g. `docs/ARGON_PROMPT_01_<topic>.md`) instead of inline in chat, so the whole prompt can be selected and pasted into another tool in one action. Confidence: 0.65
- Expects such a file to contain one self-contained fenced block (the prompt verbatim) rather than prose sections mixed with the payload. Confidence: 0.6
- Reports UI/layout bugs with a screenshot plus a one-line symptom ("the roster is more that the screen"), no repro steps and no file path — expects the agent to locate the responsible UI code itself, fix it, and not come back with clarifying questions. Reinforced when a deploy window overflowed the viewport and the whole report was one typo-laden line ("the swindow is out if the screen") with only a screenshot attached, and again when a HUD overlap was reported as "the day is covering the free summon" — the user's label may not match the on-screen string, so the agent must map the colloquial name to the real element from the screenshot (grep the visible text, e.g. "DAY" / "Free Tickets") and fix it with no clarifying question. Confidence: 0.85
- Frames regressions with "now I can't ..." wording ("it should show the mouse when option came now i cant choose") — expects the agent to treat previously working interaction as the baseline, find which detection/visibility rule broke it, and fix the root cause rather than the symptom. Confidence: 0.65
- Gives terse, image-anchored UI/3D design requests ("make the option better to [Image #1]") with no prose, no file path and no spec — expects the agent to work out which surface is meant, hunt for the referenced image in the workspace/scratchpad when it does not arrive, and either propose concrete design options or author a ready-to-paste prompt for an external 3D-capable AI and implement the returned spec, instead of asking an open-ended "what did you mean?". Confidence: 0.75
- Packs several distinct bugs into one run-on, typo-laden sentence attached to a screenshot ("...and a and d make me move in a circle like make them strick 1 axis") — expects every complaint in the message to be parsed out and fixed in a single pass, with no clarifying questions back. Same for several cleanup chores lumped into one terse, lowercase line ("there are alot of junk code dead code unused md and unupdated readme"): every listed item is in scope for that single pass. Confidence: 0.75
- Reports camera/input-feel bugs with a screenshot plus a terse, typo-laden symptom ("the curser move out of the screen and up to make the moving infite") and expects the agent to identify the underlying engine limitation and fix it at that level (real pointer lock) rather than patching the symptom. Confidence: 0.7
- Reports gameplay control-mapping bugs by stating the intended mapping and the broken part in one terse, typo-laden line ("the right click should be for defece and left fro atk but teh left dotn work") — expects the agent to trace the whole input path (defaults, save/load, options switch polarity, on-screen hints) and make the mapping consistent everywhere, with no clarifying questions. Confidence: 0.75
- Reports "wrong trigger" UI issues with a screenshot plus a terse, typo-laden constraint ("ask this notification only if i was going to go to a floor with out a wepon not always") — expects the agent to enumerate every place the prompt can fire (window open, tutorial step, world interaction, action button), keep only the commit-point trigger, and swap the passive surfaces to inline/non-blocking feedback, with no clarifying questions. Confidence: 0.7
- Accepts multiple-choice design proposals that embed ASCII "CURRENT vs PROPOSED" wireframes and a clearly marked recommended option; picks the recommended design immediately without further discussion. Confidence: 0.65
- Accepts multiple-choice scope questions that carry a code-level preview of each option (file list, API surface) plus a recommended option; answers with the recommended choice and then grants the whole scope. Reinforced by a cleanup run where the agent batched four independent decision dimensions into one question set (how aggressive on code, how to handle historical QA docs, fix vs delete broken dev cheats, delete vs keep orphaned artifacts/media), each option described concretely with counts and file names, and every recommended option was confirmed. Confidence: 0.7
- Describes a desired interaction flow in a terse, typo-laden sentence attached to a screenshot ("it is asking me to summon but what it have to be is if i want to enter the floor without the weapon it should") — expects the agent to redesign the prompt/dialog into the requested choice, wire every entry point of that flow (window button, hotkey, world interaction, hint text) and keep adjacent copy consistent (e.g. NPC dialogue lines that referenced the old wording), with no clarifying questions. Confidence: 0.7
- Issues single-word shorthand commands with no screenshot, file path or spec ("compact"), referring to whatever was just worked on — expects the agent to resolve the referent from the immediately preceding work and act on it directly instead of asking what is meant. Reinforced by a typo-laden one-liner git instruction ("puch it to main") that names no branch, file list, commit message or verification. Confidence: 0.65
- When asked to load the project rulebook, expects the rules restated as an actionable operating checklist rather than a paraphrase of the file: short numbered items grouped by concern (testing, scope/protected paths, code conventions, codemap, ambiguity handling, report format) with the exact commands named (`node --check <file>`, `node scripts/check_codemap.mjs` → "CODEMAP OK"), the protected path list and the report cap (≤15 lines, 3 manual test steps) quoted inline, and a closing line asking for the task (either "What do you want to work on?" or "Ready for your task."). Reinforced by a fresh standalone "read th agent md" opener answered with a concern-labelled bulleted checklist ending in "What do you want to work on?", and again by a later "read the agent md" opener answered with a labelled bullet list of the rulebook sections ending in "Ready for your task.". Reinforced by another typo-laden "read teh agent md" opener answered with a concern-labelled bullet checklist (workflow, testing, scope/protected paths, code, codemap, report format) that also proactively listed the dirty working-tree files (including one in a protected path and an untracked scratch dir) with a note that they would not be clobbered, then asked "What are we building?". Confidence: 0.7
- When delivering a code review / bug-hunt, reports each finding as a fixed template: title, severity (critical/high/medium), exact file + line numbers, the wrong code quoted verbatim, why it is wrong with concrete in-game reproduction steps, the fix as a minimal code diff, and which other files the fix could break (blast radius). Confidence: 0.65
- Ranks review findings by real player impact with an explicit priority order (crash > data loss > feature-that-never-works > visual glitch) and wants style, naming, and missing comments ignored when judging/ranking. Confidence: 0.65
- Does not want an investigative sweep artificially capped at the requested count (e.g. "top 5"): report every significant finding even if it exceeds N, and append a short list of one-line suspects that could not be fully proven rather than stopping at the proven set. Confidence: 0.6
- Briefs for parallel agents follow a fixed structure — ISSUE (symptom + expected behaviour) → PERMISSION (the exact files that may be edited, everything else forbidden) → WHAT TO DO (file-by-file, naming the exact API/CSS/technique to use and the behaviour that must not change) → VERIFY (the exact allowed commands, and what must not be run) → FINAL REPORT (≤15 lines, 3 manual test steps, risks, "CODEMAP updated: yes/no") — and expects each section to be honoured as written. Confidence: 0.75
- Names the exact technical mechanism inside the brief (e.g. "use event.target.closest(...) against the window root class", "stopPropagation only, never preventDefault", "passive: true", "overscroll-behavior: contain") so the executor implements it literally instead of substituting its own equivalent approach, and expects the chosen mechanism to be explained in the final report when reality differs from the brief's assumption. Confidence: 0.7
- Reports NPC/AI movement problems as a screenshot plus one terse, typo-laden expectation ("when i summon the chacter i want them to use the stair not jump the fence") with no file path — expects the agent to locate the route/waypoint source, make the characters follow the real walkable geometry, and make every consumer of that route share the same corrected path instead of patching one system. Confidence: 0.7
- When asked to prepare a handoff report for another AI, do not change any code: only read the project and write the requested report file. Make it complete, exact and copy-paste ready: include the exact requested sections, paste full code (not summaries), state measured/verified facts (e.g. triangle counts), and end with a 'SAFE TO REPLACE' list naming files/functions that can be rewritten independently. Confidence: 0.75
- For refactor-audit reports handed to another AI, keep them compact and code-free: write only file paths, line counts, names, numbers and short descriptions (no pasted code), while still following the exact requested sections. Confidence: 0.65
- When asked for replacement code, output the complete replacement file(s) as full code, ready to paste, with the file path above each block, and no explanation beyond a short (e.g. 5-line) summary of what changed. Confidence: 0.7
